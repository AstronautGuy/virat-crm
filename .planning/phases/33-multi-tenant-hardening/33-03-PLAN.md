# Phase 33 Gap Closure Plan 3: Admin Sales Edit Feature

## Goal
Implement a sales edit feature for Admins as requested during UAT ("i want the edit feature for the admins too").

## Proposed Changes

### `src/server/api/routers/sales.ts`
- **Feature**: Add an `updateSale` mutation.
- **Logic**: 
  - Restrict to `Admin` (and possibly `Manager` for their own branch/team).
  - Handle updating the sale details (amounts, address, customer details).
  - *Note*: If items are changed, inventory needs to be reverted and recalculated. This involves significant complexity (reversing previous `inventoryTransactions`, updating `inventory`, and creating new transactions).

### `src/app/sales/[id]/edit/page.tsx`
- **Feature**: Create a new page for editing sales.
- **Logic**:
  - Fetch existing sale data and pre-fill a form (similar to `src/app/sales/new/page.tsx`).
  - Submit the changes via the `updateSale` mutation.

### `src/app/sales/page.tsx`
- **Feature**: Add an "Edit" button to the Sales detail sheet for Admins.
- **Logic**: Link the "Edit" button to `/sales/[id]/edit`.

## Note on Scope
Since Phase 33 is exclusively for "Multi-Tenant Hardening (tRPC & REST Gateways)", adding a full CRUD feature for Sales (including complex inventory reversion logic) represents significant scope creep. 

**Recommendation**: Defer this minor gap to a subsequent phase (e.g., Phase 34: Admin Tooling & Editing Capabilities) to maintain phase boundaries. If you wish to proceed immediately, run `/gsd-execute-phase 33 --gaps-only`.
