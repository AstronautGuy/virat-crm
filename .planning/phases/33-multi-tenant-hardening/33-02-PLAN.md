# Phase 33 Gap Closure Plan 2

## Goal
Fix remaining multi-tenant hardening gaps where an Employee can see other employees' sales entries and the unauthorized "Approve/Reject" buttons. Additionally, fulfill the user request to show the employee name on the sales widget and support clicking on a sales entry to view its expanded details.

## Proposed Changes

### `src/server/api/routers/sales.ts`
- **Issue**: `getSales` filters by `branchId` for non-admins but doesn't restrict by `userId` for Employees.
- **Fix**: Update `getSales` to add a filter: `if (currentUser.role === "Employee") { whereConditions.push(eq(sales.userId, currentUser.id)); }`

### `src/app/api/rest/sales/route.ts`
- **Issue**: The REST API also filters by `branchId` but not by `userId` for Employees.
- **Fix**: Add a condition: `if (user.role === "Employee") { whereConditions.push(eq(sales.userId, user.id)); }`

### `src/app/sales/page.tsx`
- **Issue**: Approve/Reject buttons are rendered for Employees, who lack authorization to click them.
- **Fix**: Retrieve the current user's role via `api.users.getMe.useQuery()`. Only render the Approve/Reject buttons if `user.role === "Admin" || user.role === "Manager"`.
- **Feature (Widget Employee Name)**: Update the `CardDescription` to display the employee who created it using `sale.user.firstName` and `sale.user.lastName` alongside the customer name.
- **Feature (Expanded View)**: Implement a `Sheet` or `Dialog` component. When a user clicks on a sales `Card`, open the Sheet to show the full sales details (amounts, status, customer info, creator info, and files).

## Verification Plan
1. Log in as an Employee. Verify you can only see your own sales in the sales list and the REST API.
2. Verify the Approve/Reject buttons are no longer visible to Employees.
3. Verify the sales widget displays the name of the employee who created the sale.
4. Verify clicking on a sales entry opens an expanded detailed view.
